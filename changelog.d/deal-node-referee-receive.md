- `deal node referee receive` checks a referee's Result against both parties' halves and seals it into a node book as received, or seals why it was refused (evidencebook#624): `--book ID --result FILE --parties FILE --received-type T --refused-type T --half-type T`. `--result` is `{"capsule": <the referee's sealed Result Capsule>, "document": <base64 of the Result document exactly as written>}` and `--parties` is `{"buyer": {"half", "action", "terms"}, "seller": {...}}`. The check is capsule-engine's Go referee package (`go/referee`, `BindOpenings` then `VerifyResult`, required at v0.6.0), plus this node's own: its key must have signed one of the halves (`not_a_party`) and the document must be the referee's JCS bytes (`result_mismatch`). A Result that fails is refused and the refusal sealed with its code, never silence, and the verb exits with it. Receiving is safe to repeat: a Result already received and a half already held seal nothing again, so a retry after an interruption resumes. What it shows is what the Result and the halves say, not that the referee's judgment is right. The record type names are the node's own. `capsulectl/go.mod` requires `github.com/action-state-group/capsule-engine/go` v0.6.0 (was v0.3.0).
