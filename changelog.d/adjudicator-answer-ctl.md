### Added: capsulectl-deal answers an adjudicator in full and rules over four books (#861)

- `deal respond` answers an adjudicator's request for an x-deal-v1 deal (derivation `deal_adjudicator_copy/1`, subject the deal's correlation) with the full adjudicator copy: the whole deal book, the copy of the other side's book the party holds, and the book's facts trimmed to the copy (`xdealv1.TrimBookEvidence`), in one answer file `{"request", "bundle", "facts"}`. It has no selective form. A request for a deal the profile does not hold is refused `no_such_subject`, and one whose `--requester` is not the adjudicator the agreement names is refused `not_authorized`. Each answer and each refusal of a held deal is linked by an x-deal-v1 `answer` record in the party's journal.
- `deal ruling --answer FILE` (at most one per party, beside the case-opening `--copy` files) reads the case with `xdealv1.GatherCase`: the ruling carries `sources`, and the output lists each side's book read with each record's time and what timed it (`own_stamp` or `holder_link`). A ruling against a side none of whose records was read is refused (Steven's ruling 2, u211). Without `--answer`, `deal ruling` reads the case as before and writes no `sources`.
- `deal receive` prints a ruling's `sources`, a source the adjudicator did not read as "not shown to the adjudicator", and a fork as "the signer's book forked at N". A capsulectl-deal release before this one refuses a ruling that carries `sources`.
- `capsulectl/go.mod` requires evidencebook at 341af3ed, the library with the full adjudicator copy and `GatherCase` (#877).
