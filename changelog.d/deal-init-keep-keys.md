- `deal init --signing-key-file F --checkpoint-key-file F` keeps an existing key instead of making one (evidencebook#624): a PKCS#8 PEM (the form a Python Goose node's `producer.key` and `checkpoint.key` are in) or a 64-hex Ed25519 seed, so the key id a peer knows the node by stays. The key is copied into `--dir` as a hex seed and the source file is not changed; a key that is neither is refused before anything is created, and a key not given is made fresh as before. This starts a new store: the history of an earlier home is not carried into the new profile or its History card, and stays readable where it is.
