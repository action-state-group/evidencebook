- capsulectl-deal writes a bundle's witnessed chain as `parent-log-witness/v1` (Evidence Bundle -03), which AAC's verifier checks, in place of `x-cadence-witness/v0` (evidencebook#737, Sherlock2's ruling on capsule-cli#428): the six bundle builders (a deal report, a History's deal members, a sale's bundle, a terms result's share and `deal node bundle`) and the deal page's witnessed flag. The block is the chain with its `cadence` member named `parent`; members -03 does not define (`state`, `extent`, `checkpoint_at`, `steps_witnessed`, `steps`, `rest`) stay in it, which a verifier ignores. A bundle never carries both names. A checkpoint that is not yet witnessed (scheduled, pending, unverified, not configured) has no chain to carry, so its state keeps the old name, which no verifier reads as a witness. capsulectl-deal still reads `x-cadence-witness/v0` and the names before it. **Readers:** a capsulectl whose core is v0.1.0-rc47 or earlier checks only `x-cadence-witness/v0`, so it reads a new bundle's witness as not checked; use capsule-cli v0.1.0-rc50 or later, which verifies `parent-log-witness/v1`.
