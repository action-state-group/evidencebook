- `deal node request`, `deal node respond` and `deal node reply-check` give a node's own book on the deal profile's shelf the evidence-request exchange (evidencebook#624). `deal node request --book ID` is the core's `request` verb on a node book: `--request FILE --responder KEY --output FILE` asks and records the request, `--response FILE --for RECORD --responder-key KEY --responder-checkpoint-key KEY` records the answer after verifying it under the pinned keys (an answer under other keys is refused and never recorded, so it cannot foreclose the request), and `--absent-until TIME --for RECORD` records that nothing came back once the waiting window has closed. `deal node respond --book ID --request FILE --output FILE [--requester ID] [--policy FILE]` answers a request addressed to the node with a signed reply and records it; to anyone, with no `--requester`, only the public questions (the checkpoints and checkpoint_range subjects and the `history_card/1` and `history_card/2` derivations) are answered and everything else gets a signed refusal, and an authenticated requester is also answered `standard_history/1` (counts only) unless the policy turns it off; with `--requester` and the default policy a record is served only to the counterparty it names, and the records `deal node append` and `seal-model-call` seal name none, so by default they go to no one; a policy with `history_segments` `peers` serves any record of the node book by its subject to any requester the operator authenticated, with the record's Capsule (its digests, not its payload originals, so a sealed prompt does not leave) and its statement members. `--requester` is for an identity the transport authenticated, never a name the requester declared. `deal node reply-check --reply FILE --request-digest D --signer KEY` says whether a reply parses and carries the responder's signature for that request, records nothing, and is the check a reply gets that arrives after its request's absence was recorded; it does not check the answer under the pinned checkpoint key or the witness receipts, as recording an answer does, so a late reply that passes it is not a recorded, verified answer. The request, the recorded answer and the recorded absence are signed records of the node book, and so is an answer or refusal to a well-formed request from an authenticated requester; a malformed request or one with no `--requester` is answered without a record. The transport (a relay, a pipe) is the host's. A deal's book, the cadence and the journal are refused, as for `deal node append`.
