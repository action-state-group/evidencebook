- `deal node request`, `deal node respond` and `deal node reply-check` give a node's own book on the deal profile's shelf the evidence-request exchange (evidencebook#624). `deal node request --book ID` is the core's `request` verb on a node book: `--request FILE --responder KEY --output FILE` asks and records the request, `--response FILE --for RECORD --responder-key KEY --responder-checkpoint-key KEY` records the answer after verifying it under the pinned keys (an answer under other keys is refused and never recorded, so it cannot foreclose the request), and `--absent-until TIME --for RECORD` records that nothing came back once the waiting window has closed. `deal node respond --book ID --request FILE --output FILE [--requester ID] [--policy FILE]` answers a request addressed to the node with a signed reply and records it; with no authenticated requester only what the share policy serves to anyone is answered. `deal node reply-check --reply FILE --request-digest D --signer KEY` says whether a reply is an artifact or a refusal that the responder signed for that request, records nothing, and is the check a reply gets that arrives after its request's absence was recorded. Each is a signed record of the node book; the transport (a relay, a pipe) is the host's. A deal's book, the cadence and the journal are refused, as for `deal node append`.
